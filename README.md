# 摇跳卫士 Shake Guard

## 0.1.1 排查修复

- 修复将无障碍事件时间与 `elapsedRealtime()` 比较的问题，改用同一 `uptimeMillis()` 时钟；旧版在设备累计休眠超过约 1 秒后可能丢弃全部正常事件。
- 同一应用的界面分区变化不再无条件清除启动保护状态，也不会延长原时段；其他包的分区变化仍保守清除状态。
- 首页区分系统设置中启用与服务实际连接，新增用户主动开启的 60 秒本地诊断，可看到未匹配、点击放行、过期事件和保护超时的原因。诊断与普通日志共用 200 条上限，最多保留 7 天；开启诊断意味着短时记录其他应用包名，不采集正文。
- 录屏可见“微博 → 系统打开确认框 → 淘宝”。目前仍不自动穿过系统确认框匹配规则，也不自动点击系统按钮。无法仅凭视频确认服务配置、实际包名或唯一失败原因。出现此框时可直接点取消。

复测建议：覆盖安装 0.1.1，确认服务显示“已连接”，总开关开启；规则选择“微博 → 淘宝”，先观察记录。若仍不匹配，开启 60 秒诊断，返回桌面重新打开微博复现，然后回到本软件查看记录。

免 Root 安卓应用：在用户配置的启动保护时段内，观察来源应用到目标应用的可疑跳转，按规则仅记录或尝试一次系统返回。

**这是跳转后的补救工具，不能阻止目标应用启动，也不能准确判断摇动或广告。** 近期没有收到点击事件并不能证明用户没有主动操作。登录、支付、分享可能被误返回，请先验证仅记录模式。

## 使用

测试安装包：[下载 0.1.1 APK](downloads/shake-guard-0.1.1-debug.apk)。请登录有权访问此私有仓库的账号后下载。

1. 安装 `shake-guard-0.1.1-debug.apk`（Android 8.0 及以上）。这是测试签名版本，适合试用，不是商店发布包。
2. 打开应用，添加“广告所在的来源应用 → 被打开的目标应用”规则，默认仅记录。可从启动应用列表选择，或手填包名。
3. 阅读授权说明，前往系统无障碍设置开启“摇跳卫士跳转防护”，再打开首页的规则检测开关。
4. 从桌面打开来源应用，在配置的前 3～15 秒内复现广告跳转，然后检查本地记录。
5. 确认规则适用后，编辑该规则启用自动返回。误判时关闭此规则，或在首页暂停 5 分钟。

保护时段从服务观察到来源应用进入前台开始，不是从进程启动开始。已在前台的应用需要离开后重新进入。进入首页查看或修改规则会清除临时判定状态。系统中转、同包网页和某些广告 SDK 可能无法覆盖。

如果系统提示侧载应用受到限制，请在确认 APK 来源后自行按设备提示处理。厂商省电策略可能停止服务；首页显示打开页面时的服务连接快照，之后仍可能断开。服务不通过连续按返回或强制启动来源应用来补偿失败。

## 隐私与权限

- 无 Root、无网络权限、无传感器监听、无悬浮窗、无全量安装包查询。
- 无障碍服务仅处理窗口包名、点击事件类型和时间，不访问事件文字、节点树或截屏。
- 可见的启动应用列表用于用户选择规则。
- 本地匹配日志最多 200 条，读取或写入时清除超过 7 天的记录，可手动清空。停止使用后不会后台定时清理，卸载将删除数据。
- 自动返回必须由用户逐条启用，可随时关闭总开关、删除规则或停用无障碍服务。

## 开发与构建

原生 Java 17 + Android SDK 35 + Android Gradle Plugin 8.9.2 + Gradle 8.11.1。原设计中的 Kotlin 改为 Java，减少初版语言插件和运行时依赖。最低 API 26，目标 API 35。正式商店发布前需重新核对目标 SDK 与无障碍 API 政策。

安装 Java 17 与 Android SDK 后配置 `JAVA_HOME`、`ANDROID_HOME`，执行：

```powershell
.\gradlew.bat assembleDebug lintDebug
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-engine.ps1
```

macOS / Linux：

```sh
sh gradlew assembleDebug lintDebug
mkdir -p /tmp/guard-tests
javac -encoding UTF-8 -d /tmp/guard-tests app/src/main/java/io/shakeguard/app/RuleEngine.java app/src/main/java/io/shakeguard/app/EventTiming.java tests/RuleEngineTest.java
java -cp /tmp/guard-tests io.shakeguard.app.RuleEngineTest
```

APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。GitHub Actions 配置会执行规则测试、构建和 lint，并上传测试 APK 构件；远程运行结果请查看仓库的 Actions 页面。

Windows 首次本地准备工具的辅助脚本位于 `scripts/prepare-tools.ps1`，可自动下载并解压官方工具；随后运行 `scripts/build-local.ps1`。普通开发者也可通过 Android Studio 配置 SDK 和 JDK，使用标准 Gradle Wrapper。所有本机构建缓存与工具目录均被 Git 忽略。

## 规则实现

`RuleEngine` 不依赖 Android，可独立测试。只匹配直接的来源 → 目标变化，重复来源窗口不重置进入时间，来源最近 1.5 秒观察到点击时放行。每次匹配有 3 秒冷却，自动规则最多发送一次返回指令，随后观察 2 秒确认是否回到来源。系统未接受返回、已发送返回、确认回到来源分别记录，不当作同一种成功。

事件按包名和类型进行启发式处理，无法仅凭这些字段可靠证明窗口就是完整前台 Activity。同包界面分区变化保留原保护时段，其他包的分区变化清除临时状态。系统窗口、异常事件顺序和厂商行为仍可能影响结果。
